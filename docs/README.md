## Cómo leer estos documentos

Cada etapa del flujo tiene su propio documento de planificación. Antes de
escribir código de una etapa, su `.md` debe estar cerrado y acordado.

| Documento | Estado |
|---|---|
| [00-arquitectura-global.md](00-arquitectura-global.md) — stack, contratos entre agentes, decisiones transversales | Borrador |
| [01-entrada-y-direccion.md](01-entrada-y-direccion.md) — captura del brief y Director IA | En discusión |
| `02-investigacion-y-estrategia.md` | Pendiente |
| `03-contenido-y-creatividades.md` | Pendiente |
| `04-aprobacion-y-ejecucion.md` | Pendiente |
| `05-analitica-y-optimizacion.md` | Pendiente |

## Convenciones

- **Decisión abierta** marca un punto que requiere respuesta antes de codificar.
- **Supuesto** marca algo que asumimos y que puede invalidarse más adelante.
- Las etapas se numeran igual que en el diagrama de arquitectura.
